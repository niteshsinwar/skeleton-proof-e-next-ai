# Baseline rules this project cites

Pinned from the engineering baseline **version 1.26** when this project was rendered. Rules, skills and
docs here cite rules as `[02/A5]`; this file holds the exact text of every rule cited, so the reasoning travels
with the project even where the baseline isn't available. Generated by the skeleton (`sync_baseline_rules.py`);
never edit it by hand: `copier update` refreshes it. Each rule's evidence and sources live in the baseline.


## 01: 01 — Architecture: shape, flow and scale

| ID | Rule |
|---|---|
| 01/AL2 | Rate-limit store: In-process for P; **Redis with atomic scripts** (or Postgres if Redis isn't otherwise needed) for S/E |
| 01/AL3 | Shedding priorities: human interactive > agent > batch/prefetch; safety, audit and approvals never shed |
| 01/AL4 | Load-test tool: **k6** with CI thresholds |
| 01/C1 | **By tier:** P → PaaS, Cloudflare/Vercel or one container · S → containers on a PaaS or ECS/Cloud Run with managed Postgres, object storage and a staging environment · E → IaC, separate accounts or projects per environment, private networking for data, guardrails on the model gateway, documented RTO/RPO. |
| 01/C4 | **The product can be demonstrated at zero spend** (fixtures and AI-off mode) and estimates its model and infrastructure cost in the README. |
| 01/C5 | **Model access goes through a model gateway** (allowed models and routing, credentials and region, redacted logging, timeouts and retries, token and spend tracking, version metadata, fallback, policy for sensitive workloads). |
| 01/R1 | **Write the capacity assumptions down before choosing components:** human users and agent clients (peak concurrent, requests/s each), read/write mix, peak multiplier (e.g. 10× spikes), latency targets (p95/p99 per journey), data growth, monthly cost budget. Revisit them when a roadmap trigger fires (DB CPU > 70%, p95 over target, a single failure takes everything down, deploys > 30 min). |
| 01/R2 | **Rate limits and quotas are layered:** per principal (human, agent, service), per tenant, and per endpoint class, with **cost units** for expensive work (LLM calls, SMS, exports). Flow control uses token bucket or GCRA; monthly quotas use fixed windows. One instance → in-process; several → a shared store with atomic updates. **Fail-closed or fail-open when the limiter's store is down is written down per endpoint class.** Interactive → `429` + `Retry-After`; async → queue. |
| 01/R3 | **Agents are a traffic class of their own:** separate quotas from humans, idempotency keys mandatory, pagination limits enforced, results cacheable where permissions allow, and **humans protected first under load**. |
| 01/R4 | **Load shedding by priority:** every request is tagged with a criticality (interactive human > agent > batch/prefetch); under saturation the lowest tier is shed first with a **fast 429/503, not a queue**; adaptive concurrency limits (latency-driven) at the edge or middleware. **Safety checks, audit writes and human approvals are never shed.** |
| 01/R5 | **Graceful degradation is designed:** a static or cached fallback for reads; **the product still runs with AI switched off**; bounded-staleness cache reads during a DB incident; a degraded mode is always visible to users. |
| 01/R6 | **Bulkheads and deadlines:** a separate connection pool per dependency; a request deadline propagated to every downstream call; **retry budgets** (not only per-call retries) so retries can't amplify an outage. |
| 01/R7 | **The database scaling ladder, one rung at a time on a measured trigger:** query and index fixes → connection pooling (PgBouncer transaction mode; prepared statements need PgBouncer **≥ 1.21** with `max_prepared_statements` > 0, and **≥ 1.22 with our psycopg 3 driver** (13; W61)) → read replicas for lag-tolerant reads → table partitioning → sharding or a DB per domain. |
| 01/R8 | **The caching ladder:** none → in-process LRU → shared cache. Keys include tenant, permission scope and version; TTL **and** explicit invalidation; stampede protection; **authoritative state used for a decision is never served from cache**. |
| 01/R9 | **Load is tested, not assumed:** k6 scenarios for the key journeys, including agent traffic patterns. Thresholds (p95, error rate) from a measured baseline are pass/fail in CI, **verified to both pass and fail**. Smoke on every change; spike and soak before major releases (tier S/E). |
| 01/R10 | **Add infrastructure only on its trigger:** broker (DB queue too slow / many consumers) · Redis (shared cache or limits across instances) · dedicated vector DB (pgvector too slow at measured scale) · graph DB (multi-hop queries unreadable in SQL) · search engine (FTS can't rank) · Kubernetes (many services + a platform team) · microservice (S3) · multi-agent (an eval proves the gain). A component in compose with no code using it is a defect. |
| 01/S1 | **The tier (P / S / E) is chosen at discovery and recorded in ADR-0001.** When in doubt, take the **higher** tier for data and security and the **lower** tier for infrastructure. |
| 01/S2 | **Modular monolith by default:** one deployable, one database, modules with boundaries enforced by the layering test (locked B1). |
| 01/S3 | **Split out a separate service only for a named reason:** a different scaling or resource profile (GPU/LLM worker, long parser) · a different trust or failure domain (sandboxed parsing of untrusted uploads, a credential-holding tool server) · a different team and deploy cadence · a runtime or platform constraint · compliance isolation. Each split is an ADR naming the reason and the metric. **Not** "it looks modular" or "we may need it". |
| 01/T1 | **The API tier is stateless;** every kind of state has one named home: system of record (Postgres or the owning SaaS) · audit (append-only) · workflow/agent checkpoints (separate schema, **never** the record) · sessions (DB, cache or signed cookie) · cache (disposable) · files (object storage) · vectors (pgvector, with the embedding space recorded) · behaviour config (versioned data). |
| 01/T2 | **Pick the flow by duration and audience:** the user waits and it takes under a few seconds → synchronous (stream progress for LLM work) · longer than ~10 s, bursty, scheduled or fanned out → a **job** (`202` + job resource) · several consumers react to one fact → **events via the outbox** · scheduled batch over many records → scheduler → orchestrator → workers. |
| 01/T3 | **Events:** published only after commit (outbox); at-least-once delivery with **idempotent consumers**; per-entity sequence numbers; versioned event schemas; a visible dead letter. CQRS or event sourcing only by ADR on a measured need. |
| 01/T4 | **Jobs** use the locked job contract (business idempotency key, bounded retries, visibility timeout, dead letter, traffic-independent reaper) behind a port; a broker (SQS/Redis/Kafka) is added only when the DB queue's throughput or fan-out is measured to be insufficient. |
| 01/T5 | **Concurrency:** optimistic versions on aggregates; idempotency keys on retried writes; no unit of work held across a provider call. Request handling is async end to end (resolved by 13/SK2). |
| 01/T6 | **Process-local state forces a single coordinator;** anything shared across instances lives in the DB or a shared store. |

## 02: 02 — Backend, API, data model and auth

| ID | Rule |
|---|---|
| 02/A1 | **Commands are named** (`POST /orders/{id}/submit`), never `PATCH {status}`. "A state field a client can write is a state machine a client can drive." |
| 02/A2 | **Routers hold no business logic;** each calls one use case. Exceptions are listed in the rule with their reason; known debt is listed, not hidden. |
| 02/A3 | **One command, one transaction:** load + expected version → authorise → domain command → update with version+1 → audit event → outbox row → commit. Any failure rolls everything back. **The route commits; use cases and repositories never do.** |
| 02/A4 | **Optimistic concurrency at the edge:** strong `ETag` on reads; `If-Match` required on writes (missing → `428`, stale → `412`); `409` only for a domain conflict. |
| 02/A5 | **Idempotency keys on every side-effecting POST**, mandatory for agent clients: the key is scoped to actor + command + target; a replay returns the same status and body; reuse with a different payload is rejected; the retry attempt is never part of the key. |
| 02/A6 | **Errors are RFC 9457** `application/problem+json` with a stable `code`, `correlation_id` and field errors. `detail` is user-safe (no stack trace, SQL, secret or raw provider text). |
| 02/A7 | **The status-code contract is a table in the rule:** 422 names the broken invariant; 409 lists legal transitions; **404 for both unauthorised and absent, with the same body**; 429 and 503 carry `Retry-After`; **a provider outage never fails open**. |
| 02/A8 | **Property-level authorisation (OWASP API3):** request models are strict and reject unknown fields (no mass assignment); response models are explicit allowlists per caller (no excessive exposure). |
| 02/A9 | **Pagination:** an **opaque cursor** (keyset underneath) with an enforced maximum page size for every list; offset only for small admin lists. |
| 02/A10 | **Versioning:** additive changes need no new version. A breaking change ships as a new version with a deprecation notice and a sunset date, and **the committed OpenAPI snapshot diff flags breaking changes in CI**. |
| 02/A11 | **The OpenAPI document is the contract:** committed, diffed, and the source of the generated frontend client. **Every route has an HTTP test naming its path** (enforced by the Stop gate); a schema that claims validation names the test that proves it. |
| 02/A12 | **Health vs readiness:** `/health` is liveness plus the **build SHA**; `/ready` checks the DB, **migration revision == code head**, and config, never just "port open". |
| 02/A13 | **Every endpoint has resource limits (OWASP API4):** payload, upload and page size, timeouts, and **per-principal and per-tenant rate limits and quotas**. Expensive endpoints (LLM, SMS, exports) get stricter quotas and cost budgets. Responses use `429` + `Retry-After`; the draft `RateLimit` headers are optional. |
| 02/A14 | **Long work returns `202` with a job resource** (status, owner, input refs, progress, retries, output ref, error code, cancellation); nothing waits on an open HTTP request. |
| 02/A15 | **Unsafe consumption (OWASP API10):** outbound calls go only to allowlisted hosts (no SSRF), and third-party responses are validated as untrusted input. |
| 02/A16 | **"Endpoints that must not exist"** are listed in the rule and asserted by tests (e.g. no bulk-approve, no route that lets a model execute SQL). |
| 02/B1 | **Dependencies point inward** (api → application → domain ← adapters). The domain imports nothing internal. Enforced by an **AST-walking layering test** with a forbidden map per layer, which **reports how many modules it examined**. |
| 02/B2 | **Module per concern, not file per function;** a folder only when two or more files share a theme; no confusable file names. The directory map lives in `.claude/rules/backend.md`, and adding a package updates it in the same commit. |
| 02/B3 | **Ports are shaped by what the domain needs** (`typing.Protocol`); one adapter per vendor. **Least privilege through the interface**: the audit port has append and correction, and no update or delete. |
| 02/B4 | **One registry per extensible thing** (tools, AI steps, checks, packs), keyed uniquely; a module on disk that isn't registered fails a test. |
| 02/B5 | **What varies is configuration, not code.** Business config is versioned, effective-dated, owned by the business, and read by a strict loader that **rejects unknown keys**. Process settings (env, DSN) are separate. Non-secret settings are tracked; secrets are not. |
| 02/B6 | **Constructors refuse illegal states;** value objects are immutable. **Domain objects are never ORM instances**: repositories rebuild them through constructors, so invariants can't be skipped on load. |
| 02/B7 | **Errors are explicit:** no bare `except`, no fallback that looks like success, and **a degraded path records its degradation in the result**. Expected data problems come back as results; bugs raise. |
| 02/B8 | **One module owns all model calls and usage accounting; one owns all audit writes; one owns each external system.** Correlation, causation and actor travel in `contextvars`, with JSON logs. |
| 02/B9 | **Algorithms state their complexity where n can grow**, bound their input, and **fall back when the bound is exceeded**. Money is in integer minor units (or Decimal) with a currency; time is UTC `timestamptz`; **waiting time is a union of intervals, never a sum**. |
| 02/B10 | **Static analysis is a test lane:** ruff (including pyflakes) and `mypy --strict` gate every commit. They catch silent non-execution that tests miss. |
| 02/BL2 | Domain vs ORM objects: **Domain objects are never ORM instances**; persistence models map through constructors |
| 02/BL4 | Primary keys: UUIDv7 everywhere |
| 02/BL7 | Identity: External OIDC identity provider; backend verifies only; local accounts only at tier P. **Resolved by 13/SK4:** IdP-agnostic OIDC, a mock OIDC server locally, the production IdP chosen per project by ADR from the 13 shortlist. **Amended by Nitesh, 2026-11-04:** email + password accounts are our own at any tier (Better Auth inside the Next.js server, accounts in our Postgres, its published keys verified by the API, so the API still never mints); outside identity providers only for SSO, OAuth, enterprise login and two-factor |
| 02/BL8 | Webhooks: Standard Webhooks format both ways |
| 02/BL9 | Security target: **OWASP API Top 10 covered by tests at every tier; ASVS 5.0 L1 at P, L2 at S, L3 for regulated E** |
| 02/D1 | **Postgres by default, with the same engine in tests;** the test DB is never the dev or demo DB. |
| 02/D2 | **Migrations from the first table:** autogenerate is a candidate to review (it **drops tables it can see but doesn't know about**); CI runs up **and** down on a scratch DB; never edit an applied migration; readiness checks the head. |
| 02/D3 | **Zero-downtime changes:** expand → backfill in batches → contract; `CREATE INDEX CONCURRENTLY` (then check for invalid indexes); **`lock_timeout` set before DDL**; constraints added `NOT VALID` then validated; no table-rewriting type changes on large tables. |
| 02/D4 | **Table and column checklist:** plural `snake_case` tables, typed ids (`order_id`), **UUIDv7** keys, `created_at`/`updated_at` as UTC `timestamptz`, `created_by`, `version`; NOT NULL by default with explicit defaults; CHECK constraints for ranges and enums; FKs with an explicit `ON DELETE`; unique constraints on business keys; units in column names; **a PII class recorded per column**; JSONB only for genuinely schemaless payloads, with a schema version. |
| 02/D5 | **Indexes are designed:** every FK indexed; composite order = equality columns then range; partial indexes for hot subsets; **`tenant_id` leading** in tenant tables; verified with EXPLAIN; unused indexes removed. |
| 02/D6 | **Audit is append-only:** insert-only grant, hash chain at tier E, corrections as new rows, an independent verifier. **Never claim immutability**; say tamper-evident. |
| 02/D7 | **Schema per owner, with grants as the control** (app, audit, rag, obs, eval, agent checkpoints — 01/T1); grant tests run under `SET LOCAL ROLE app_role`. |
| 02/D8 | **A deletion policy per entity** (soft vs hard, written down); GDPR erasure follows a data map across every derived store (logs, caches, vector index, eval sets). |
| 02/D9 | **Configuration that changes behaviour is data:** versioned, effective-dated, resolved by date, pinned by the records that used it, and never edited once pinned. |
| 02/D10 | **Deliberate absences are listed and tested** (e.g. no soft delete on audit, no confidence column, no protected attributes). |
| 02/D11 | **The store follows the data's shape:** relational for the record; vectors only for retrieval, with the embedding space recorded; graph traversal in Postgres first; KV, search or time-series only on a measured trigger. **Never everything in a vector store.** |
| 02/D12 | **Live state is queried, never retrieved** from an index (status, balances, what's in force now). |
| 02/D13 | **Workflow state** is a set of named states entered by named commands; holds are intervals, not states; an illegal command leaves no partial state and writes no audit. |
| 02/D14 | **Concurrency columns** (`version`) on mutable aggregates; `SKIP LOCKED` only for queue-like rows. |
| 02/D15 | **Backups are restored on a schedule** to prove they work; tier E adds a two-person rule for backup access. |
| 02/D16 | **Generated and synthetic data** come from one deterministic command, are labelled in the data, and released datasets are immutable. |
| 02/I1 | **An adapter per vendor behind a port;** fakes only for what a sandbox can't give (injected failures, expiry); live sandbox tests prefix test records and clean up. |
| 02/I2 | **Every outbound call** has a timeout, bounded retries with jitter **and a retry budget**, a circuit breaker, and its own connection pool (bulkhead). |
| 02/I3 | **Frozen downstream contracts:** never change what a consumer reads (**adding a key counts**); diagnostics go to our logs. |
| 02/I4 | **Inbound webhooks:** verify an HMAC signature over the **raw body** with constant-time comparison; reject timestamps outside ~5 min; **dedupe on the webhook id**; acknowledge fast, then process asynchronously and idempotently; accept several signatures during key rotation. Outbound webhooks follow the same format. |
| 02/I5 | **Reconciliation jobs** compare our state with the external system on a schedule; drift is a finding, not a silent fix. |
| 02/I6 | **Contract tests on upstream schemas,** so a renamed field fails loudly instead of returning nulls. |
| 02/I7 | **Production is read-only to scripts;** write methods are stubbed so writes are impossible by construction, unless a human authorises a specific write. |
| 02/J1 | **No unit of work is held across a provider call:** gather in one transaction, call the model, re-check the version, write in a second. |
| 02/J2 | **A DB-backed queue behind a port by default** (library chosen by spike): states queued → running → awaiting review → done or failed; a **business idempotency key**; bounded retries; a visible dead letter; a visibility timeout; **a reaper for stuck jobs that doesn't depend on traffic**. |
| 02/J3 | **Events go through an outbox, published after commit;** consumers are idempotent; ordering uses **per-entity sequence numbers**; event schemas are versioned. |
| 02/J4 | **Scheduled jobs:** a single-run lock (no overlap), a written missed-run policy, an explicit time zone, idempotent bodies. |
| 02/J5 | **Process-local state requires a single coordinator**; otherwise it lives in the DB or a shared store. |
| 02/J6 | **A generation id fences late output** from superseded runs. |
| 02/J7 | **Fan-out reconciles:** results returned must equal units dispatched, or the run is flagged. |
| 02/Z1 | **Verify, never mint.** The backend verifies signed tokens from the identity provider against a **pinned JWKS** (algorithm allowlist, `iss`, `aud`, `exp`, `nbf`). There is no auth-bypass flag; an unconfigured JWKS means every request is `401`. |
| 02/Z2 | **Human login is OIDC authorisation code + PKCE (S256)** with exact redirect-URI matching and `state`/`nonce`. No implicit flow. |
| 02/Z3 | **Phishing-resistant MFA (passkeys/WebAuthn)** offered from tier S and **required for privileged roles at tier E**; SMS one-time codes are never the only factor. |
| 02/Z4 | **Sessions:** short-lived access, **refresh tokens for public clients rotated or sender-constrained** (RFC 9700 §2.2.2), access tokens audience-restricted to the minimum scope (§2.3), no password grant, inactivity and absolute timeouts, **re-authentication for sensitive operations**, and immediate revocation on logout or role removal. |
| 02/Z5 | **Authorisation is data and is checked per object (OWASP API1):** a role → capability matrix; every handler taking a user-supplied id checks object access before acting; **never trust a client-supplied role or actor**. |
| 02/Z6 | **Separation of duties and dual authorisation** for sensitive configuration and approvals; no self-approval. |
| 02/Z7 | **Three kinds of principal:** humans; **agents acting for a user** (the user's permissions ∩ the agent's scopes); **service principals** (client credentials, their own minimal scopes). Every audit record stores the principal type and on-behalf-of. |
| 02/Z8 | **Agents and MCP clients calling our APIs** use OAuth with protected-resource metadata (RFC 9728), resource indicators (RFC 8707) and **audience validation**; tokens are short-lived and scoped per server and task; no token passthrough. |
| 02/Z9 | **The tenancy model is an ADR:** shared schema + `tenant_id` + row-level security by default (tier S); schema- or DB-per-tenant when compliance demands it (tier E). |
| 02/Z10 | **Row-level security done right:** `FORCE ROW LEVEL SECURITY`; the app role is not the table owner and has no `BYPASSRLS`; the tenant is set with **`SET LOCAL` inside the transaction**; policies have `USING` + `WITH CHECK`; **fail closed when the tenant is unset**; views use `security_invoker`; tests run as the app role. |
| 02/Z11 | **Tenant everywhere:** every row, job, cache key, log/trace tag, rate limit, file path and vector chunk carries it; **tool and MCP credentials are encrypted per tenant**; filter before ranking or aggregating. |
| 02/Z12 | **Personas:** roles change defaults and permissions, never vocabulary; real-time feeds are per-role projections. |
| 02/Z13 | **Secrets** live in a secret manager, never in the repo, the deployed tree or logs; separate keys per environment and service; **rotate on any exposure**. |
| 02/Z14 | **Security tests per gate:** positive and negative permission, cross-tenant access, BOLA on every id-taking route, stale version, required evidence, and refusal of AI or system actors on human acts. |

## 03: 03 — Frontend

| ID | Rule |
|---|---|
| 03/F1 | **Routes are thin:** params, authorisation check, the reads the page needs, layout. No markup a component could hold, and **no logic a test needs**. Shaping and decisions move to `lib/`, where they are unit-testable (async server components are not). |
| 03/F2 | **Components are organised by business area** (one folder per area, holding its panels and its view) plus `shell/` (chrome) and `ui/` (primitives). The directory map lives in `.claude/rules/frontend.md`; **a new folder updates the map in the same commit.** |
| 03/F3 | **Split at the client boundary, not at a line count.** A client component pulls its imports into the bundle. **No god pages**: one page held six views in 1,736 lines. |
| 03/F4 | **One transport, one client module per resource, with types generated from the backend's OpenAPI.** No hand-written copies of API types. |
| 03/F5 | **API ↔ UI sync is checked:** every served operation has a call site (or is declared server-only), and every call site maps to a served operation. **What the backend exposes and no screen shows is a finding.** |
| 03/F6 | **Reads render on the server by default** *(Next)*. A client query cache (TanStack Query) is used only for interactive, frequently refreshed, user-driven data *(both)*. **One fetch pattern** handles loading, error and toast; no copy-pasted fetch blocks. |
| 03/F7 | **Writes go through one helper:** read the version (ETag) → send a *named command* with `If-Match` → refresh. Never PATCH a state field. |
| 03/F8 | **Authoritative entity data is not cached client-side beyond the request.** Live progress is a resumable projection replayed from the recorded event log, not a client-side guess. |
| 03/F9 | **Auth in the browser:** the session is a secure, httpOnly cookie, so **tokens are never reachable from JavaScript**. Hiding or disabling a control is an affordance, **never a control**; the server authorises every action. |
| 03/F10 | **The URL is state:** tab, filters, selection and step live in the URL, so every view is deep-linkable and survives a refresh. |
| 03/F11 | **Tokens only.** No literal colour, size or shadow in a component; semantic tokens in one tokens file; themes switched by `data-theme` on `<html>`, **set before first paint**. |
| 03/F12 | **Identity colour and judgement colour are separate scales that never touch.** Status colour never stands alone without a text label. |
| 03/F13 | **Closed scales** for spacing, type (few sizes), radius and shadow (one level). **No inline styles**: about 60% inline styling was why nothing stayed consistent. |
| 03/F14 | **Own your components on unstyled primitives:** a small primitive set (Card, Pill/Status, Button variants, Field with label and error, Table, Toast, SidePanel) plus product composites. **Every data component ships empty, error and loading states, or it doesn't merge.** |
| 03/F15 | **Motion only for state change** (~120 ms ease-out), with `prefers-reduced-motion` respected. No decorative hover lifts. |
| 03/F16 | **Speak the reader's language.** Every domain identifier shown on screen goes through **one labels module** (glossary headwords or plain words). **No engineering vocabulary on any screen** (no ids, hashes, "not built", route names). Raw ids stay available in detail and audit views; translation never removes. |
| 03/F17 | **Design per persona** (occasional user: guidance and plain language; daily expert: density and keyboard; approver: summary, evidence, no ambiguity). **Density is a token per persona.** Roles change defaults and permissions, **never vocabulary**. |
| 03/F18 | **A multi-step process is a journey, not tabs:** what's done, what's happening, what's left, who holds it. Show "stage 4 of 7", **never a fake percentage**. |
| 03/F19 | **AI output carries its provenance one glance away**, is visibly marked as AI-drafted, and shows **what it could not verify**. **An abstention is shown as itself, never as agreement.** No bare confidence numbers beside judgements. |
| 03/F20 | **Consequence friction gradient:** reading is frictionless; consequential actions are deliberate (evidence beside the button, required reason on override, **no bulk accept**). **Never write an audit claim the UI didn't earn.** |
| 03/F21 | **Traces show *why*:** render the recorded decision signals (rule, signal, score), **never hard-coded explanation strings**. Long AI work streams stage status, and the answer appears after validation. |
| 03/F22 | **Accessibility: WCAG 2.2 AA, measured** (automated axe checks in e2e on key pages, plus a keyboard pass), not asserted. |
| 03/F23 | **Frontend tests:** `lib/` logic unit-tested; prohibitions asserted only in the region where the defect would appear; **no negative assertion over an empty render**; the test runner's include pattern is **all test files**, never a list of present folders; e2e on critical journeys proves the **screen**, not the API response. |
| 03/F24 | **The artefact you ship is the artefact you test:** build once; CI smoke-tests that the built artefact serves its assets; the production start command matches the build output mode. |
| 03/F25 | **Framework discipline:** read the *installed* version's docs before writing framework code; check package names are the live ones; pin versions; pin the Node version (`engines` + `.nvmrc`; `engines` alone is advisory unless the package manager enforces it, 13). Public sites only: prerender with JSON-LD, sitemap, robots, `llms.txt`, self-hosted assets, and a content overlay that degrades to static. |
| 03/F26 | **Budgets are numbers, measured on real users at p75:** LCP ≤ 2.5 s, **INP ≤ 200 ms**, CLS ≤ 0.1, plus a JS budget per route. Checked in CI by a lab check on the built artefact for key pages (the skeleton uses Playwright with `PerformanceObserver` and a script-bytes check per route; Lighthouse CI is an equivalent) and in production (web-vitals reporting). Optimise percentiles, not averages. |
| 03/F27 | **Perceived speed:** stream the page shell first and fill it with **Suspense boundaries close to the data**, pushing awaits down to the component that needs them; **skeletons match the final layout** (so no layout shift); prefetch the likely next route; long AI work streams its stages. |
| 03/F28 | **Every interaction answers within a frame.** *Low-risk, reversible* actions are optimistic, with explicit rollback and a toast on failure. **Consequential actions are never optimistic**: they wait for the server and show progress (F20). |
| 03/F29 | **Large data stays off the main thread and out of the DOM:** cursor pagination or virtualised lists keyed by stable ids; debounce inputs that trigger requests (~250–300 ms); heavy computation in workers or on the server. |
| 03/F30 | **Images and fonts never shift the layout:** explicit dimensions and the framework's image optimisation; fonts self-hosted, variable, `swap` with a size-adjusted fallback, two or three families at most. |
| 03/F31 | **Every query declares its freshness** (`staleTime`) by data class: reference data hours, user data seconds to minutes, live state pushed. No refetch-on-focus storms; one owner per query key (each observer runs its own polling timer). |
| 03/F32 | **Choose the transport by how the data changes:** rarely changes → server render + cache (`use cache`/`cacheLife` or HTTP cache) · changes only when the user acts → fetch on demand and **invalidate exactly the affected keys** after the mutation · changes on its own over minutes → **poll**, paused when the tab is hidden, stopping when done (the interval function returns `false`) · changes in seconds or for many viewers → **server push** (F36). |
| 03/F33 | **HTTP caching on API reads:** an explicit `Cache-Control` on every response (`no-store` for personal and authoritative data, long-lived only for public static assets), with **ETag → `304`** for revalidation. CDN caching only for public content. |
| 03/F34 | **The client respects backend back-pressure:** on `429`/`503` it honours `Retry-After`, retries with exponential backoff and jitter, and never retries non-transient errors. |
| 03/F35 | **Server-Sent Events by default** for server→client updates (auto-reconnect, `Last-Event-ID` resume); **WebSocket only when the client must also send** in real time. Resume works because the server replays from the **recorded event log**. |
| 03/F36 | **Real-time auth:** the session cookie (`SameSite`) **plus an Origin allowlist**, or a **short-lived single-use ticket** fetched over HTTPS; **never a long-lived token in the URL**. Authorise each message and event, not only the connect, and send each persona only its own projection. |
| 03/F37 | **Connection hygiene:** a heartbeat (~15–30 s), reconnect with jittered backoff, **one connection per tab** multiplexing all subscriptions, and the connection closed when the tab has been hidden for a while. |
| 03/F38 | **Content Security Policy with per-request nonces** on the authenticated app (no inline scripts), plus HSTS, `frame-ancestors`, `nosniff`, `Referrer-Policy` and `Permissions-Policy`. Public static pages, which can't carry a nonce, use a hash-based or strict static CSP. |
| 03/F39 | **CSRF in depth:** `SameSite=Lax/Strict` session cookies + the framework's Origin check + **a CSRF token on sensitive actions** (CVE-2026-27978 bypassed the Origin check from a `null` origin); never allow `'null'` as an origin. |
| 03/F40 | **Never authorise in middleware alone** (Next.js 16 calls it `proxy`; CVE-2025-29927 bypassed it): check in the server action or route *and* in the backend. Session UX: warn before expiry, re-authenticate **without losing form state**, and logout revokes the session server-side. |
| 03/F41 | **Readable text:** body line length 45–75 characters (`max-width: ~66ch`), line height ~1.5, body text at least 16 px, paragraph spacing generous. **Layouts must survive WCAG 1.4.12 text spacing**: no fixed-height text boxes, no `!important` on text. Tabular numerals in data columns. |
| 03/F42 | **A type system, not ad-hoc sizes:** one variable sans-serif family (+ one mono for data and code), 6–7 sizes on a scale, weights used for hierarchy. |
| 03/F43 | **Forms:** a label is always visible; validate on blur and on submit (not every keystroke); the error sits beside the field and says what to do; **user input survives a failed submit**; the server is the authority and client validation is a convenience. |
| 03/F44 | **Feedback timing:** every action is acknowledged visually at once; anything over ~1 s shows progress; long tasks can be cancelled; **no silent failures**: every error is visible with a next step, and error text never shows stack traces or ids (the backend's `detail` is user-safe). |
| 03/F45 | **Empty states teach** (what this is, and the first action); destructive actions name the object, confirm, and offer undo where reversible. |
| 03/F47 | **Every screen passes the six-lens review** in the skeleton's `/review` skill: product designer (journey, copy, empty states) · frontend engineer (rendering, budgets) · backend/system designer (calls, caching, push vs poll) · security (auth, CSP, CSRF) · accessibility and tester (axe, keyboard, journeys) · cloud and ops (artefact, CDN, headers). |
| 03/F48 | **Errors are monitored in production:** JS errors, unhandled promise rejections and failed resource loads go to an error tracker with source maps, tagged with release SHA and correlation id, never with PII. |
| 03/F49 | **Product analytics are named events** (journey steps, task completion, drop-off), kept separate from performance and error telemetry, with no personal data in event properties. |
| 03/F51 | **Dependency admission:** before adding a UI dependency, ask "can we get 90% without it?", then check maintenance activity, licence and bundle cost; record the answer in the PR. |
| 03/F52 | **A living component catalogue** (Storybook or equivalent) documents every owned primitive with its states (default, loading, empty, error, disabled). |
| 03/F55 | **Ready for other languages from day one:** no hard-coded strings outside the labels module, locale-aware dates, numbers and currency, logical CSS properties; locale tests when a second language is added. |
| 03/FL3 | Data fetching: Server reads by default *(Next)*; TanStack Query for interactive data *(both)* |
| 03/FL10 | Performance budgets: LCP ≤ 2.5 s · INP ≤ 200 ms · CLS ≤ 0.1 at p75, enforced in CI |

## 04: 04 — AI systems: the product's AI, agents, prompts, context, RAG and memory

| ID | Rule |
|---|---|
| 04/G1 | **The least-autonomous pattern that works:** single augmented call → prompt chain → routing → parallelisation → orchestrator–workers → evaluator–optimiser → autonomous agent. A workflow when the steps are predictable; an agent only for open-ended work. **Name the pattern honestly** ("bounded iterative retrieval" isn't an agent). |
| 04/G2 | **One agent with good tools before many agents.** Split only for context isolation, true breadth-first parallelism, or different permission levels, **and only when an eval shows the gain is worth the extra tokens.** |
| 04/G3 | **The orchestrator sequences everything; agents never call agents directly.** Handoffs are typed `{from, to, goal, constraints, budget}` and recorded; sub-agents get isolated context and return **conclusions, not transcripts**, reporting incrementally. |
| 04/G4 | **Multiple independent agent flows** each have their own failure domain, budget and owner; **no shared mutable state** (they coordinate only through recorded events and idempotent jobs); one writer per resource; **dispatched == returned** is checked at fan-in. Don't fan out beyond provider quota. |
| 04/G5 | **Runtime budgets on every run:** max steps and tool calls, tokens, money and wall-clock; **loop and no-progress detection**; a heartbeat. Hitting a budget escalates with a context package; it never silently stops. |
| 04/G6 | **Durable, resumable runs:** state persisted after **every** model call; the checkpointer is never the system of record; resumed nodes re-execute from the top, so **no side effects before an interrupt** and an idempotency key on every write; **re-validate preconditions against live state on resume**. |
| 04/G7 | **Approvals and plan mode:** read-only tools may run automatically; write-class actions need an approved plan or an approval showing the evidence; a human gate sits where evidence is complete and nothing irreversible has happened. |
| 04/H1 | **Oversight is chosen by consequence:** approve before acting (irreversible, financial, legal) · review a draft · sampled review · escalate on missing evidence · staged autonomy **only where the action is the product and measured error rates justify it**, never where a human decision *is* the product. **Scrutiny is never routed by raw model confidence.** |
| 04/H2 | **A gate leaves evidence:** the reviewer sees the evidence, the risk reason and what the AI couldn't verify; the approval records what they saw; independent-first review (human view recorded before the AI draft is revealed) for high-stakes judgements. |
| 04/H3 | **Fairness by matched pairs:** two inputs differing only in a protected or proxy attribute must produce the same outcome; protected attributes are never stored. |
| 04/H4 | **Transparency:** users are told they're dealing with AI, see the sources, and have a path to a human. |
| 04/IL2 | Multi-agent policy: Allowed only with an eval showing the gain over one agent, a token budget, and G3/G4 controls |
| 04/IL3 | Structured output: Provider schema-constrained output + Pydantic validation in the app |
| 04/IL4 | Long-term memory: Only from human-confirmed outcomes |
| 04/K1 | **One tool registry** serves local and MCP tools. Tools are narrow, typed and authorised server-side; **read tools execute, write tools return proposals behind approval**; tools are scoped per step (fewer tools is tested, not assumed). |
| 04/K2 | **Every tool call:** validated and capped input, timeout, a retry policy with max attempts, **result validation (empty, null or schema-drifted output is a failure)**, an audit event and a trace span. Add tools one at a time and verify each. |
| 04/K3 | **MCP in the product:** allowlisted servers, OAuth with audience validation, **tool descriptions treated as untrusted text** (pinned, reviewed, diffed), per-tenant encrypted credentials. |
| 04/K4 | **Agent-generated code runs only in a sandbox** with reset and teardown; no shell access by default; general code execution only by ADR at tier E. |
| 04/M1 | **Models are chosen by tier and evals:** small for classification and routing, balanced by default, large for hard reasoning and orchestration; **measure before downsizing** and escalate low-confidence cases; all calls go through the model gateway (locked C5). Compliance (ZDR, BAA, residency) can rule a model out. |
| 04/M2 | **Model change control:** a model or reasoning-effort change re-runs the eval suite and gates first; retirement dates are tracked; effort settings are tuned by measurement. |
| 04/M3 | **Cost is evidence:** the four numbers never merged; the per-attempt usage record; budgets per task and tenant; the Batch API for non-urgent volume. |
| 04/M4 | **Data sent to a provider is minimised:** an explicit exclusion list is the LLM boundary; PII is redacted where not needed; the provider's retention terms are checked against the data class. |
| 04/P1 | **Know what a model is:** it can be confidently wrong; when context is missing it doesn't see a gap, it fills one, differently each time, in the same fluent tone. The failure that reaches users is "plausible, well-formatted and wrong". So: **specify or don't delegate · declare what is absent · make "I cannot" a valid output · bound every input.** |
| 04/P2 | **Ask "could plain rules or search solve enough?" first.** Use a model only where its four properties (fluency, broad knowledge, a finite window, steerability on concrete instructions) beat code, then apply the **delegation test**: is a wrong call reversible? what does it cost? who must answer for it? |
| 04/P3 | **Every AI feature has a decision-ownership table** (code / model / human) written before the code and enforced in code. No hidden layer may overrule the declared owner, in either direction. |
| 04/P4 | **Security, permission, money and state transitions are code-owned.** Deterministic floors are **one-directional** (they may raise risk or block, never lower or unblock). **A model can't police its own input.** |
| 04/P5 | **Fail closed:** provider down, malformed output or a timed-out safety check → block, escalate or abstain, with `503` + `Retry-After`; never "proceed unchecked". |
| 04/P6 | **The model reports facts; code decides.** Never ask a model for a value it wasn't given: it cites supplied ids with **verbatim spans**, and code attaches identity and verifies by exact substring; **reject, never repair**. **Hide the scoring rubric** from the model (it isn't told which fields are mandatory or how results are scored). Deterministic tools compute figures for the model to compare. |
| 04/P7 | **Known limitations are designed for, not discovered:** misattribution (real id, wrong span) · ~86% run-to-run verdict stability · bias from labels even with valid citations · a schema is a floor, not an assurance · preference-tuned models *want* to answer · reasoning tokens share the output cap and can truncate answers · models retire and parameters drift. |
| 04/Q1 | **An agent is a folder of versioned files**: one file per version holding contract (incl. what it must never do and who decides after it), grounding, policies, prompt and a **reference to its eval set** (the cases live once, in `evals/datasets/`: 12/NL8). A prompt-only change is a new version; versions named in recorded runs are hash-pinned; **no prompt text at call sites**. |
| 04/Q2 | **The system prompt states** role, task, rules, output format and **what to do when unsure** (abstain or escalate); XML tags separate instructions, documents and examples; retrieved text is marked as data. |
| 04/Q3 | **Prompt rules are one sentence, about a class of case, never an instance;** edit the existing rule for a field rather than stacking a second; the file keeps the history of what was tried. |
| 04/Q4 | **Structured output uses the provider's schema-constrained mode** (Claude structured outputs or strict tools) where available, **and is still validated in the application**; enumerations are allowlisted; the invalid-output retry rate is a metric; a length-truncated output is invalid, never salvaged. |
| 04/Q5 | **Abstention is a first-class output** with its own field; it is recorded as itself and **never read as agreement**. A judgement that no verified claim supports is an abstention. |
| 04/X1 | **A context ledger for every call:** each item has source, trust tier, tenant, sensitivity, permission decision, token cost and `may_drive_action`; **dropped items are logged with a reason** (no silent truncation). Each agent version declares its grounding and token budget. |
| 04/X2 | **Order for cache and attention:** stable content first (system rules, tools, policies, examples), then volatile content; restate the question after the evidence; no timestamps or request ids near the top; check that cache reads are non-zero. |
| 04/X3 | **Long-running context is managed deliberately:** compaction, tool-result clearing and memory files, with essential facts written to memory before anything is cleared. |
| 04/X4 | **RAG follows the data's shape** (prose → hybrid + measured rerank; exact ids → lexical; aggregates → validated SQL plan; relationships → graph traversal; small stable corpus → in the prompt). **Filter by permission and version before ranking**; lanes fused with RRF; every lane re-measured per corpus release; chunk on structure (AST for code); embedding space recorded with blue/green re-indexing; **per-class abstention, never a score threshold**. |
| 04/X5 | **Retrieve stable knowledge; query live state.** Status, balances and "what is in force now" come from the system of record at request time. |
| 04/X6 | **Three records per attempt** (what the model was shown, what it asked, what it said), joined by one attempt id. Consumers read the **verified** result, never the raw payload; a gated value gates every copy returned. |
| 04/X7 | **Memory tiers:** short-term (last N turns verbatim + deterministic compaction) · session (a resumable state record) · **long-term only from human-confirmed outcomes**, keyed to the entity, with provenance, tenant scope and erasure. Agents never "continuously learn" from unconfirmed output. AI results are cached only by exact match (identity scope + corpus version + prompt version). |

## 05: 05 — Security and governance (cross-cutting)

| ID | Rule |
|---|---|
| 05/SG1 | **Remove before you watch:** a missing capability beats a guarded one (no write tool beats an approved write tool; no PII field beats a redacted one). Every control fails closed and **says how it fails**. |
| 05/SG2 | **The layered safety stack** is filled in for every AI-touching system in `docs/architecture/security.md`. Each layer says how it fails: input (size, type, injection screening, scope) · context (permission-filtered retrieval, external text marked as data) · model (**never a control on its own**) · tools and actions (least privilege, argument validation, read vs propose, approval) · output (schema validation, redaction, grounding check) · human (approval queues, sampling, escalation) · monitoring (audit, alerts, kill switch). |
| 05/SG3 | **The threat model is sized by tier and kept current:** P → a 10-line list of assets, who could abuse them and the one control for each · S → STRIDE over the container diagram + the SG2 stack + the OWASP LLM Top 10 walk (SG4) · E → a full model with data-flow diagram, retention settings and incident playbook, **reviewed with security before launch**. It is redone whenever a trust boundary changes (new integration, upload path, tool, tenant model). The `/threat-model` skill drives it. |
| 05/SG4 | **AI risks are walked against OWASP Top 10 for LLM Applications 2025**, each mapped to its locked control (§2); **the OWASP Top 10 for Agentic Applications (2026) is mapped the same way in §2b**. |
| 05/SG5 | **Prompt injection is assumed to succeed sometimes, so the defence is structural:** external content (documents, emails, web pages, tool results, tool descriptions) is segregated and marked as data; **the model never holds a credential** (tokens stay in application code); tools are least-privilege and **writes are proposals**; output is validated in deterministic code; high-risk actions need a human. Adversarial cases live in the one versioned eval caseset by tag (06/E3). **"Tell the model to ignore instructions" is never the control.** |
| 05/SG6 | **Uploads are hostile:** authenticated, authorised and CSRF-protected · extension **allowlist** checked after decoding the name · Content-Type **and** magic bytes (each insufficient alone) · size cap **and decompressed-size cap** (ZIP/XML bombs), page and frame caps · **server-generated names** · stored in object storage outside the web root, served through an id → file handler that checks authorisation · malware scan or CDR where required · images re-encoded with metadata stripped · **parsing in a sandboxed worker** at tier E and for public uploads at S (01/S3 trust domain). |
| 05/SG7 | **Data is classified on day one** (public · internal · confidential · regulated) per table or field in the data-model doc. The class decides logging, retention, residency, what may reach a model (04/M4) and what may appear in an eval set. |
| 05/SG8 | **Redaction is deterministic and always runs:** validators and patterns run on every path; the model may *add* redactions, never skip them. Logs, traces, fixtures and eval sets carry no PII or secrets; dev and demo use **synthetic data labelled as synthetic** unless real data is authorised. |
| 05/SG9 | **Compliance is spotted at discovery, owned by a named person, and never quoted from memory:** GDPR (lawful basis, minimisation, purpose, erasure across derived stores per 02/D8, residency, DPIA, transparency about automated decisions) · HIPAA (**a signed BAA before any PHI is sent**; only eligible features) · authorised environments (e.g. FedRAMP) · zero-data-retention terms (an agreement, not a toggle) · sector rules (named decision owner, oversight, explainability, retention basis). The `/discover` question bank asks; legal review answers. |
| 05/SG10 | **Audit content:** who, what, when, before and after, reason, correlation id, and for AI steps the prompt version, model and evidence ids. **Design every write as if someone will ask about it in 18 months.** An audit entry records what actually happened, **never what the UI assumed**. Storage mechanics are locked in 02/D6. |
| 05/SG11 | **Kill switches:** every AI feature, agent, side-effecting tool and integration can be switched off at runtime, per tenant, without a deploy. Flags are an **audited control plane** (who flipped what, when, why), and the product keeps working with them off (01/R5). |
| 05/SG12 | **Secrets beyond storage** (02/Z13 owns storage): agents can't read them (10/H9 deny rules); **no production `.env` snapshots on laptops**; runtime secret-pool state stays out of deploys; **a secret that touched git is rotated even after history is rewritten**; dev tokens are labelled, scoped to local use and invalid elsewhere; expiry is monitored (07/O18). |
| 05/SG13 | **Security gates:** CI runs secret scanning (gitleaks everywhere; GitHub push protection where the plan includes it, W62), dependency audit, SAST, SBOM and image scanning (tools in 13/SK8), the OWASP API Top 10 tests (02/BL9), negative-permission and cross-tenant tests (02/Z14). PRs touching auth, data, uploads, tools or AI get the `security-reviewer` subagent and the §4 checklist. ASVS level by tier (02/BL9). |

## 06: 06 — Testing and evals

| ID | Rule |
|---|---|
| 06/E1 | **Evals are written alongside the behaviour, never after;** each case states what "good" means before its expected output. The eval author can't edit the prompts it grades. |
| 06/E2 | **Eval layers:** L0 architecture and invariants (hard gates at 100%) · L1 deterministic contract quality · L2 retrieval · L3 grounded generation · L4 behaviour and consistency · L5 human utility · L6 operations and cost. **Capability evals and regression evals both run.** |
| 06/E3 | **Datasets:** sources are anonymised production cases, expert-written cases, reviewed synthetic cases, **every past failure** and adversarial tags (injection direct/indirect/encoded, contradictory, out-of-scope, thin, absent). Released versions are immutable; gold sets are frozen; **the model never labels its own exam**; matched pairs for fairness; a held-out set; **no one-sided (imbalanced) evals**. |
| 06/E4 | **Non-determinism:** every real-model case runs **N ≥ 3** and reports per run ("2 passed, 1 failed"); fixes are proven red → green on the real model; production data is split at model and prompt cut-overs; logs are searched for degradation markers; denominators are checked; **evals run the production configuration**. |
| 06/E5 | **Graders:** code first (schemas, exact match, tool-call correctness); an LLM judge with an **anchored rubric**, both orders, a different model family, and **calibrated against human labels (Cohen's κ ≥ ~0.6) before it gates anything**; humans for ground truth. **A judge is not independent human review.** |
| 06/E6 | **Metrics by layer, never averaged into one score:** context precision and recall, faithfulness, answer relevance (RAG); extraction fidelity, consistency, refusal correctness, **edit distance read with review time** (domain); safety and security rates; cost and latency per task. Reported per category. |
| 06/E7 | **Recorded runs are the evidence:** a score with no recorded run is a claim; recorded runs are never overwritten; a harness proves its own verdict in a labelled fixture mode, both ways; AI resources are hash-pinned by enumeration. |
| 06/E8 | **Release gates:** the offline suite runs before any prompt, model, retrieval or corpus change; **regressions block**; one variable changes at a time; online: sampled evals, shadow runs, canaries; **read transcripts**, not just scores. |
| 06/E10 | **The feedback flywheel has an owner:** human corrections, rejections and edits become eval cases, and the stores are designed so exporting them is a query, not a project. |
| 06/E11 | **Small differences are uncertain:** agentic eval scores carry run-to-run and infrastructure noise; repeat runs and report the spread before claiming an improvement. |
| 06/EL2 | Eval runner: **pytest-based harness** (markers, N-run parametrisation, recorded runs) with RAGAS metric names; a library (DeepEval or promptfoo) only after a pilot |
| 06/EL3 | Judge policy: LLM judges may inform, and gate only after κ ≥ ~0.6 against human labels on that rubric |
| 06/EL4 | Mutation scope: Required for tier E critical paths (decisions, money, permissions, verdicts); recommended at S |
| 06/T1 | **Lanes by what they cost, gated by marker and env var; plain `pytest` is free and offline:** unit · invariant · integration on the **real DB** (`REQUIRE_DB=1` in CI turns skips into errors) · contract (OpenAPI, events, required rows) · e2e on the built artefact · evals (real model, opt-in) · live sandbox (exclusive lock, prefixed test records cleaned up) · load (k6) · stress (destructive, opt-in) · **post-deploy smoke**. Operator scripts are never named `test_*`. |
| 06/T2 | **Red first:** a test plan from the spec (behaviour names, layer, input, **hard-coded expected output**, edge and error cases); tests written without sight of the implementation; **implementation never edits tests**; at least one error case and one edge case per happy path. A new test is seen failing, for the reason claimed, before the fix. |
| 06/T3 | **Prohibitions are failing tests:** every invariant is a named test (code and configuration paths both covered); critical invariants have independent tests, so removing one leaves others standing. Removing one needs an ADR. |
| 06/T4 | **What may be faked:** never mock the LLM to prove behaviour (only for plumbing such as retries and timeouts); never fake the database; prefer a live sandbox over a fake (fakes return what the author imagined); inject time, randomness and ids; a deterministic provider is labelled and never counted as an eval. |
| 06/T5 | **Test design is a technique, not a guess:** equivalence partitioning, boundary values, decision tables and state transitions for case derivation; **property-based tests** (Hypothesis, fast-check) for invariants and state machines. |
| 06/T6 | **Honest fixtures:** read the fixture before the test body (what state does it never reach?); pair every negative assertion with a positive case only the correct rule satisfies; **no assertion that accepts either answer**; no negative assertion over an empty render; include patterns cover all test files. |
| 06/T7 | **Mutation proves catch-power:** for critical paths a mutation check injects real faults. The proof is the **failure message**, not the red; one mutation per prohibition; mutate and revert with edits, never `git checkout`; run with no stale bytecode, on a fresh clone. |
| 06/T9 | **Defects:** classify **defect vs new requirement** first; record severity and priority separately; fix → retest → close; every bug fix ships with the test that would have caught it; regression selection = prior failures + core flows + integration points + boundaries; track escaped defects and MTTD/MTTR, not pass counts. |
| 06/T10 | **Isolation and time:** never two suites against one DB; the test DB is never the dev or demo DB; no hard-coded dates (inject the clock); local time for local gates; every resource closed (a missing `with` hung a suite). |

Every source directory is named by some rule, checked. `harness-check` parses every `paths:` block, because **a YAML error silently loads the rule everywhere**. Anything that must survive compaction stays unscoped or in CLAUDE.md. |
| 10/H3 | **One always-loaded map instead of loaded docs:** a *where-things-live* table, a *task → doc* routing table, and (once there is code) a **component registry**, one line per component. Everything else is read on demand. |
| 10/H4 | **Every rule states the failure it prevents and ends in a change contract:** Load first · Run · Same commit · Prove · Never. "A rule with no detection signal behind it is a wish." |
| 10/H5 | **Rules may only reference things that exist.** `harness-check` verifies every path and command a rule, skill or agent names. |
| 10/H6 | **Order of trust and evidence labels.** Running code and live systems > dated docs > architecture docs > comments and chat. Requirements carry a label (`BRIEF`, `USER-DECISION`, `DECLARED`, `DERIVED`, `OPEN`); **`OPEN` items get no load-bearing implementation**. Agent output and chat history are draft material. |
| 10/H7 | **Stop conditions are written down:** stop and ask (or record `OPEN`) when scope is assumed, a threshold lacks data, infrastructure facts are unknown, or an external claim has no source. "An explicit gap is acceptable. A plausible invention is not." |
| 10/H8 | **Two AIs, two harnesses.** `.claude/` builds the product; `ai/` is the product's governed runtime AI. They have separate budgets, and no mechanism crosses without evidence. |
| 10/H9 | **"Never" means a deny rule or a hook.** Committed `settings.json` denies reads of secrets (`.env*`, `*.pem`, `*.key`), destructive git and shell commands, and production deploys. Personal overrides go in a gitignored `settings.local.json`. |
| 10/H10 | **A permission protects a tool, not a property.** A `PreToolUse` hook guards protected paths across Edit, Write *and* Bash, and a git-history check backs it up for paths computed at runtime. |
| 10/H11 | **Block only on mechanical certainties; keep advisory hooks silent by default.** "A guard that misfires gets switched off; a reminder every turn trains skimming." |
| 10/H12 | **Hooks are code.** They are tested in both directions, read *this session's* state (`session_id`), and lock shared files. Protection hooks fail closed; advisory hooks exit cleanly when a tool such as `jq` is missing. Each one is documented in the hooks README, and the README is checked against what is actually wired. |
| 10/H13 | **Local guards are repeated in CI** (hooks can be bypassed; CI can't). A pre-commit granularity guard limits files and top-level areas per commit; **never `git add -A`**; `set -euo pipefail`; chain with `&&`; never read success through `\| tail`. |
| 10/H14 | **Knowledge lives in the repo, not the session:** `STATE.md` (dated current truth, ≤ 6 KB, critical-first), `decisions/`, `open-questions.md`, `ops/failure-log.md`, and a closed **scope/backlog file** whose rows are counted (cheap compaction insurance). Auto-memory outside the repo is a convenience copy: anything durable is promoted into the repo. |
| 10/H15 | **The session loop is automatic.** `SessionStart` injects STATE, git state and check results; `UserPromptSubmit` warns only when STATE drifts N commits behind; `PreCompact`/`PostCompact` leave and read a breadcrumb; `/end` rewrites STATE, appends a handoff and commits (if the model invoked it, it states the commit and waits). **Write the plan to disk before building.** |
| 10/H16 | **A finding isn't filed until it is propagated** (STATE, rules, skill and agent briefs, ADRs, glossary). A warning that lives only in a handoff reaches nobody. The test: "could tomorrow's session act on this without our chat?" |
| 10/H17 | **Every failure ends in a hardening.** The second occurrence becomes a rule, hook or test, linked to the failure-log entry. The harness has its own audit and changelog, and notes about the tool's behaviour are re-verified within 21 days. |
| 10/H18 | **Verify, don't narrate.** No "done" without command output. *Built*, *reachable*, *tested* and *shown* are four separate claims. Report the size of the set checked; read the failure message, not just the red; walk the whole tree after a reorganisation; run the real server for wire-format changes. Answer quality questions with evidence that could have failed. |
| 10/H19 | **Work protocol.** Intake: read the map → extend what exists before creating ("never a parallel structure") → for a new requirement, propose the approach in 2–3 lines and **stop for confirmation**. Plan to disk for anything over ~3–5 files. Tests red first. **Finish a known list without stopping to ask; one item at a time.** Report as *Current → After → Rules in scope*, in plain names, not codes; decisions come with options and consequences. |
| 10/H20 | **Research before trusting memory.** Read the installed version's docs and primary sources. A summary isn't a read (`LOCATED ≠ READ`). Record what was checked, with its date, in `.claude/reference/`. |
| 10/H21 | **Subagents:** a narrow role and an explicit contract; least privilege (a reviewer is read-only *and* has `disallowedTools`); state what the agent may not conclude; **report incrementally**; one writer per file set; **never fan out quota-heavy work**; tests are written by an agent that can't see the implementation. |
| 10/H22 | **MCP servers are an allowlist:** `.mcp.json` is committed; only listed servers are enabled; each is reviewed like a dependency (owner, scopes, pinned version, tool descriptions read). An unapproved server is denied. |
| 10/H23 | **Every failure has an obvious home**, chosen by this routing table: a dangerous action → deny rule or hook · a repeatable workflow → skill · a convention for an area → path rule · a fact about the project → docs/STATE · a product behaviour → test or eval. |
| 10/H24 | **Each session leaves an operating record** in its handoff: model and effort, effective permissions and tier, MCP servers exposed, files touched, approvals given, failures and recovery state. |

## 12: 12 — Directory structure: the whole skeleton tree

| ID | Rule |
|---|---|
| 12/N1 | **One tree, one home per kind of thing.** This file is the merged view; the layer maps in 02 §7, 03 §2, 06 §3 and 10 §3 are the detail. They must agree, and `make harness-check` compares the scaffold with this tree. |
| 12/N2 | **Folders exist by need and tier, never "for later":** the scaffold renders only what the tier and discovery answers need (AI? UI? tier?). No empty placeholders; a component nothing uses is a defect. What renders for each tier and answer is the §2c table. |
| 12/N3 | **Apps never import each other.** They share only `packages/contracts` (schemas), never business code. A new service is `apps/<service>/` with the same internal layout and its own data. |
| 12/N4 | **Governed AI data is separate from AI code:** `ai/` holds versioned agent files and the model registry (data, loaded strictly); `apps/api/.../intelligence/` holds the code. `evals/` sits at the root. Each has its own gate. |
| 12/N5 | **Tests live with what they test** (`apps/api/tests/`, `apps/web/tests/`); the root `tests/` holds only system lanes (load, post-deploy smoke). Operator scripts live in `scripts/` and are never named `test_*`. |
| 12/N6 | **Generated files are marked and never hand-edited:** a header line plus `linguist-generated` in `.gitattributes`; regenerated in the same commit as their source; CI regenerates and fails on any diff. |
| 12/N7 | **Names:** Python modules `snake_case`; TS/TSX files `kebab-case`; folders lowercase; numeric prefixes only for ordered reading sets; ADRs `NNNN-slug.md`; no confusable names; a folder only when two or more files share a theme. |
| 12/N8 | **Every source folder is covered by a path rule** (`paths:` in `.claude/rules/`), so Claude loads the right rules wherever it edits. The map is §4; `harness-check` fails on an uncovered folder. |
| 12/N9 | **Docs are organised by the reader's question:** front-matter on every doc (`id`, `owner`, `mutability`, `updated`, `answers`, `read_when`); designed vs built marked; historical docs move to `docs/reference/` with a banner; status is counted by script, never estimated; docs change in the same commit as behaviour. |
| 12/N10 | **Secrets and personal files never enter the tree or the image:** `.env`, `.claude/settings.local.json`, `*.pem`, `*.key` are gitignored from the first commit, and `.dockerignore` excludes them from every build context. |
| 12/NL8 | Agent files and eval sets: The agent file (04/Q1) **references** its eval set by name and version; the cases themselves live once, in `evals/datasets/` |
